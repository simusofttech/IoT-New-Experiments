Aim

To develop an educational Earthquake Vibration Detection experiment using a Raspberry Pi 4 Model B and MPU6050 accelerometer to measure changing acceleration, calculate short-window RMS vibration and activate a servo motor and buzzer when the configured alert threshold is exceeded.

The experiment also records acceleration values and alert states in a CSV file and displays the vibration RMS on a live graph.

About the Experiment

The Earthquake Vibration Detection experiment demonstrates accelerometer interfacing, digital signal processing, RMS calculation, threshold-based alert control, data logging and live graph visualization.

The MPU6050 GY-521 sensor measures acceleration along the X, Y and Z axes. These readings are transferred to the Raspberry Pi using the I²C interface.

The Python program estimates the slowly changing component of the acceleration caused by gravity and orientation. This estimate is subtracted from each measured axis to obtain dynamic acceleration.

The magnitude of dynamic acceleration is calculated and placed into a rolling one-second window. The system then calculates the Root Mean Square (RMS) vibration value.

When the RMS remains at or above the configured alert threshold of 0.08 g for at least 0.5 seconds, the servo moves to its alert position and the buzzer is activated.

The alert clears only when RMS remains at or below 0.04 g for at least five seconds. This hysteresis and hold-time logic helps reduce repeated switching between alert states.

The program continuously records accelerometer readings, dynamic magnitude, RMS and alert state into a timestamped CSV file. A Matplotlib window displays the recent RMS measurements.

Important Safety Information:

This is an educational vibration monitor. It is not designed or validated for earthquake prediction, seismic intensity measurement, building safety decisions, or emergency warning.

The 0.08 g and 0.04 g thresholds are experimental settings. They must not be interpreted as certified earthquake severity thresholds.

Real sampling frequency can vary because of I²C communication and graph rendering. The one-second RMS window is based on 50 samples rather than exact timestamp integration.

Hardware Precautions:

Use 3.3V-compatible I²C connections for the MPU6050. Confirm that the module's SDA and SCL lines are not pulled up to 5V.

The SG90 servo may require a separate regulated power arrangement capable of supplying its operating current. Do not power the servo from a GPIO signal pin.

The buzzer must be compatible with the available GPIO output or controlled through an appropriate driver.

Accelerometer Reading

The MPU6050 supplies raw acceleration readings along three axes. The Raspberry Pi converts them to units of g using the configured ±2 g scale.

Gravity Estimation

A low-pass filter estimates the slowly varying component associated with gravity and sensor orientation.

Dynamic Acceleration

The estimated gravity component is subtracted from the current measured acceleration.

RMS Calculation

Dynamic acceleration values are squared, averaged across the rolling sample window and square-rooted to calculate RMS.

Alert Activation

When RMS is at least 0.08 g for 0.5 seconds, the buzzer turns ON and the servo moves to 0°.

Alert Reset

When RMS is at most 0.04 g for five seconds, the buzzer turns OFF and the servo returns to 90°.

Data Logging and Graph

Each sample is written to a timestamped CSV file. Matplotlib displays the recent RMS readings against the alert threshold.

Procedure

  1. Arrange the Raspberry Pi 4 Model B, MPU6050 GY-521, SG90 servo, buzzer, breadboard and jumper wires.
  2. Connect MPU6050 VCC to 3.3V, physical pin 1.
  3. Connect MPU6050 GND to Raspberry Pi ground.
  4. Connect MPU6050 SDA to GPIO2, physical pin 3.
  5. Connect MPU6050 SCL to GPIO3, physical pin 5.
  6. Connect the SG90 servo signal to GPIO18, physical pin 12.
  7. Provide suitable servo power and connect the supply ground to Raspberry Pi ground.
  8. Connect the buzzer control to GPIO23 using a compatible driver or module.
  9. Check the complete circuit before powering the system.
  10. Boot Raspberry Pi OS.
  11. Enable I²C using Raspberry Pi configuration.
  12. Verify the MPU6050 at address 0x68 using sudo i2cdetect -y 1.
  13. Create the experiment folder ~/Desktop/Earthquake_Detection_System.
  14. Create the logs directory or allow the program to create it.
  15. Create and activate the Python virtual environment specified in the SOP.
  16. Install smbus2, gpiozero, matplotlib and a compatible GPIO backend.
  17. Copy the complete Python code from Explore the Code.
  18. Save it as main.py.
  19. Run python main.py from a graphical desktop session.
  20. Observe the RMS graph and normal servo position.
  21. Gently create controlled vibrations near the mounted sensor.
  22. Observe whether the RMS exceeds the configured alert threshold.
  23. Check the servo and buzzer response when the alert condition is sustained.
  24. Allow the sensor to remain still and observe the reset behavior.
  25. Open the timestamped CSV file and review the recorded measurements.
  26. Press Ctrl+C to stop monitoring safely.

Result

The Earthquake Vibration Detection experiment demonstrates accelerometer-based vibration monitoring using Raspberry Pi 4 and MPU6050 GY-521.

The system calculates dynamic acceleration magnitude and short-window RMS, compares the measurements with configurable thresholds, and activates a servo and buzzer when the alert conditions are met.

Acceleration readings, RMS values and alert states are recorded to CSV and visualized using a live Matplotlib graph.
