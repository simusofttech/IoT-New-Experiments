Aim

To monitor and indicate the state of a 5V relay using a Raspberry Pi 4B, with a green LED for relay ON and a red LED for relay OFF or safe state.

About the Experiment

The Raspberry Pi controls the relay through GPIO23 and uses GPIO24 and GPIO25 for green and red status LEDs.

When the relay is ON, the green LED turns ON. When the relay is OFF, the red LED turns ON. On a handled program exit, the cleanup block commands the relay OFF before releasing the GPIO pins.

The LEDs indicate the commanded relay state; no contact-feedback input is present. GPIO.cleanup() releases the pins, so the red LED is not guaranteed to remain lit after exit. Hardware input bias determines the relay state after cleanup or loss of power.

Procedure

  1. Connect the relay module VCC to 5V Pin 2 and GND to Pin 6.
  2. Connect the relay IN pin to GPIO23 / physical Pin 16.
  3. Connect the green LED through a 220Ω resistor to GPIO24 / physical Pin 18.
  4. Connect the red LED through a 220Ω resistor to GPIO25 / physical Pin 22.
  5. Connect both LED cathodes to GND / physical Pin 20.
  6. Confirm that the relay module uses active-HIGH logic and a 3.3V-compatible input.
  7. Save the program as relay_monitor.py.
  8. Run python3 relay_monitor.py.
  9. Observe the relay ON state with the green LED ON for three seconds.
  10. Observe the relay OFF state with the red LED ON for three seconds.
  11. Press Ctrl+C and check the relay's actual state after GPIO cleanup.

Expected Output

The relay remains ON for three seconds while the green LED is ON.

The relay then switches OFF for three seconds while the red LED is ON.

The sequence repeats continuously.

On Ctrl+C, the program commands relay OFF and red LED ON before releasing the GPIO pins. The red LED may go out after cleanup.

Result

The Raspberry Pi alternates the commanded relay state and LED indicators. On a handled exit, it requests relay OFF before GPIO cleanup. This software demonstration does not verify contact position or guarantee hardware fail-safe operation.
