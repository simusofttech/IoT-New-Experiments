Aim

To design an IoT-based Machine Condition Monitor using an ESP32 DevKitC, two simulated vibration inputs, a DHT22 temperature sensor, an OLED display, a relay module, a buzzer and a red fault LED.

The experiment identifies excessive vibration or temperature conditions and automatically changes the machine status to FAULT.

About the Experiment

Machine condition monitoring is used to observe important operating parameters and identify abnormal conditions.

This experiment uses an ESP32 DevKitC as the main controller.

Two push buttons simulate vibration sensor inputs. They are connected to GPIO18 and GPIO19.

The DHT22 sensor measures temperature and humidity. This experiment uses its temperature reading for the fault decision.

The temperature threshold is set to 50°C.

If either vibration button is pressed, or the measured temperature reaches 50°C, the system detects a machine fault.

In the original control logic, the relay output becomes LOW during a fault, while the buzzer and fault LED become HIGH.

During normal operation, the relay output is HIGH, and the buzzer and fault LED remain OFF.

The SSD1306 OLED displays temperature, vibration status and the overall machine state.

Serial Monitor provides additional monitoring information at 115200 baud.

Simulation and Hardware Note:

The uploaded experiment uses push buttons to simulate vibration. These are not physical vibration sensors.

The specified GPIO and output logic follow the supplied experiment file. The actual relay module's trigger polarity and contact wiring must be checked before using it to control an electrical load.

This is an educational monitoring experiment, not a certified industrial machine-protection system.

Relay and Buzzer Safety:

The supplied source uses GPIO26 HIGH during NORMAL and LOW during FAULT.

Many relay modules are active-LOW, which means LOW energizes the relay rather than turning it OFF.

Check the module's input polarity, 3.3V control compatibility and NO/NC contact arrangement. Do not connect a real machine or mains-powered load based solely on this example.

A directly connected buzzer must be compatible with the ESP32 GPIO voltage and current rating.

Vibration Input Monitoring

Two push buttons represent vibration detection.

Both pins use INPUT_PULLUP. Pressing either button produces a LOW input.

The program converts this active-LOW signal into a Boolean vibration status.

Temperature Monitoring

The DHT22 measures temperature in degrees Celsius.

If the measured temperature reaches or exceeds 50°C, temperatureHigh becomes true.

Combined Fault Detection

Fault Logic:

machineFault = vibrationDetected OR temperatureHigh

Any one of these conditions is enough to trigger a fault.

Normal Machine Condition

When no vibration is reported and the temperature is below 50°C, the machine status is NORMAL.

GPIO26 becomes HIGH, GPIO25 LOW and GPIO27 LOW.

Fault Condition

If vibration is detected or temperature reaches the configured limit, the state becomes FAULT.

GPIO26 becomes LOW, the buzzer output HIGH, and the red LED HIGH.

OLED Display

The OLED displays the temperature, vibration and machine status.

Sensor Read Errors

The supplied partial sketch treats an invalid DHT22 reading as temperatureHigh = false.

The reconstructed sketch retains this behavior to match the source logic, but explicitly displays the temperature as unavailable.

For real machine protection, a sensor failure should not automatically be interpreted as a safe temperature.

Procedure

  1. Arrange ESP32 DevKitC, two push buttons, DHT22, SSD1306 OLED, relay module, buzzer, red LED, 220Ω resistor, breadboard and jumper wires.
  2. Connect the first push button between GPIO18 and GND.
  3. Connect the second push button between GPIO19 and GND.
  4. Connect DHT22 DATA to GPIO4, VCC to 3.3V and GND to GND.
  5. Check whether the selected DHT22 module requires a separate DATA pull-up resistor.
  6. Connect OLED SDA to GPIO21 and SCL to GPIO22.
  7. Connect the OLED to its appropriate power and ground.
  8. Connect the buzzer signal to GPIO25 and GND to common ground.
  9. Connect the relay IN to GPIO26.
  10. Connect relay VCC and GND according to its module specifications.
  11. Connect the red LED anode to GPIO27 and its cathode through a 220Ω resistor to GND.
  12. Verify the wiring and common ground connections.
  13. Open Arduino IDE and install the ESP32 board package.
  14. Install the DHT, Adafruit GFX and Adafruit SSD1306 libraries.
  15. Create a sketch named ESP32_IoT_Machine_Condition_Monitor.ino.
  16. Copy the complete sketch from Explore the Code.
  17. Select the appropriate ESP32 DevKit board and port.
  18. Verify the sketch and upload it to the ESP32.
  19. Open Serial Monitor at 115200 baud.
  20. Observe the NORMAL condition when both buttons are released and temperature is below 50°C.
  21. Press the first vibration button and observe FAULT.
  22. Release the button and check the status again.
  23. Repeat using the second vibration input button.
  24. In the Wokwi simulation, increase the DHT22 temperature to 50°C or above.
  25. Observe the buzzer, fault LED and relay-control signal.
  26. Reduce the simulated temperature below 50°C and clear both vibration inputs.
  27. Confirm the display returns to NORMAL.

Explore More: Simulated Vibration

INPUT_PULLUP provides a default HIGH signal.

Pressing a button connects the pin to GND, producing LOW.

The program treats this LOW reading as simulated vibration.

Explore More: DHT22

The DHT22 can measure temperature and humidity. Here, only its temperature measurement is used for the machine-fault decision.

Explore More: Logical OR

The || operator means OR.

The machine enters FAULT when vibration is detected OR temperature reaches 50°C.

Explore More: Relay Logic

The original sketch sends HIGH to the relay input during NORMAL and LOW during FAULT.

The electrical action depends on the relay module's active level and contact wiring.

Explore More: OLED Display

The SSD1306 OLED communicates through I²C.

GPIO21 carries SDA, and GPIO22 carries SCL.

The reconstructed sketch uses I²C address 0x3C. Check the actual module if the display does not initialize.

Result

The ESP32 IoT Machine Condition Monitor demonstrates a combined vibration and temperature-based fault detection system.

The ESP32 checks two simulated vibration inputs and the DHT22 temperature.

Whenever a vibration input becomes active or temperature reaches 50°C, the program activates the fault outputs and changes the displayed status to FAULT.

When the fault conditions clear, the GPIO outputs return to their defined normal states.

The experiment demonstrates sensor interfacing, conditional fault logic, OLED communication, relay control signals and alarm indication.
