Aim

To develop a Wi-Fi Vibration Event Counter using an ESP32 development board, bare SW-500D vibration sensor, SSD1306 OLED display and active buzzer.

The experiment detects mechanical vibration events, counts valid sensor activations, provides audible feedback, displays the event count on an OLED and makes the count available through a Wi-Fi dashboard.

About the Experiment

The Wi-Fi Vibration Event Counter demonstrates mechanical vibration sensing, digital input monitoring, event counting, software debouncing, OLED interfacing and wireless data visualization.

The experiment uses a bare SW-500D vibration sensor. Unlike a three-pin vibration module, the bare SW-500D is a two-terminal mechanical contact device.

One sensor terminal is connected to GPIO27, while the other is connected to GND. The ESP32 enables its internal pull-up resistor so that a sensor contact closure produces a LOW input.

Each accepted HIGH-to-LOW transition increases the event counter by one. A 500 ms software lockout helps prevent rapid contact changes from being counted as multiple events.

After a valid event, the active buzzer connected to GPIO25 sounds for approximately 120 ms. The updated count is displayed on the SSD1306 OLED.

The ESP32 also hosts a local Wi-Fi dashboard that displays the total number of vibration events, the time of the last event and device uptime. A Reset Counter button clears the count.

Important:

The SW-500D is a mechanical vibration switch, not an accelerometer or calibrated vibration-intensity sensor.

The counter records accepted contact-closure events. It does not measure vibration amplitude, acceleration, frequency or physical displacement.

A 500 ms lockout reduces repeated detections but may also intentionally ignore separate vibrations that occur within the same interval.

Hardware Precautions:

The bare SW-500D does not require VCC. Connect its two terminals only as specified for the switch.

The ESP32 uses INPUT_PULLUP to maintain a HIGH signal when the switch is open. A contact closure to GND produces LOW.

Use a buzzer compatible with the ESP32's GPIO voltage and current limits. Add a transistor driver if the buzzer requires higher current.

Verify that the OLED supports 3.3V operation and uses the configured I²C address.

Vibration Detection

The SW-500D mechanically changes its contact state when vibration disturbs the internal switch. The ESP32 monitors this state through GPIO27.

Digital Input Logic

INPUT_PULLUP maintains a HIGH input while the switch is open. When the contacts close, the input becomes LOW.

Event Counting

The program detects a new HIGH-to-LOW transition. If the last accepted event occurred at least 500 ms earlier, the counter increases.

Buzzer Indication

Each accepted event activates the buzzer for approximately 120 milliseconds.

OLED Display

The SSD1306 OLED displays the vibration event count. It updates whenever the counter changes or is reset.

Wi-Fi Dashboard

The ESP32 provides a local web page displaying event count, last event time and uptime. The browser requests new data approximately every second.

Reset Function

The Reset Counter button sends a command to the ESP32. The system resets the counter and refreshes the OLED and dashboard data.

Procedure

  1. Arrange the ESP32, bare SW-500D, OLED, buzzer, breadboard and jumper wires.
  2. Connect one SW-500D terminal to GND.
  3. Connect the other SW-500D terminal to GPIO27.
  4. Connect OLED VCC to 3V3.
  5. Connect OLED GND to GND.
  6. Connect OLED SDA to GPIO21.
  7. Connect OLED SCL to GPIO22.
  8. Connect the buzzer signal to GPIO25 using a driver if its current requirement demands one.
  9. Connect the buzzer negative terminal to GND.
  10. Verify the complete circuit.
  11. Open Arduino IDE.
  12. Install the ESP32 board package.
  13. Install the U8g2 library.
  14. Select the correct ESP32 development board.
  15. Create a new sketch named Wi_Fi_Vibration_Event_Counter.ino.
  16. Copy the complete sketch from Explore the Code.
  17. Replace the Wi-Fi SSID and password placeholders.
  18. Verify and upload the program.
  19. Open Serial Monitor at 115200 baud.
  20. Observe the initial count of zero on the OLED.
  21. Note the ESP32's local IP address.
  22. Open the IP address in a browser connected to the same Wi-Fi network.
  23. Gently disturb the SW-500D sensor.
  24. Observe the buzzer and vibration counter.
  25. Verify the updated count on the OLED and dashboard.
  26. Generate additional separate vibration events.
  27. Press Reset Counter on the dashboard.
  28. Confirm the displayed count returns to zero.

Explore More: SW-500D

The SW-500D is a bare two-terminal mechanical vibration switch. It produces a contact state rather than an analog acceleration reading.

Explore More: INPUT_PULLUP

INPUT_PULLUP uses the ESP32 internal pull-up resistor so that the digital input normally reads HIGH and becomes LOW when the switch closes.

Explore More: Debouncing

Mechanical contacts can switch several times during one physical vibration. The 500 ms event lockout reduces repeated counting.

Explore More: OLED

The SSD1306 OLED uses I²C communication through GPIO21 and GPIO22. It displays the total event count.

Explore More: Wi-Fi Dashboard

The ESP32 runs an HTTP web server. The browser fetches event information as JSON and updates the displayed counter.

Explore More: Reset Counter

The browser sends an HTTP POST request to the reset route. The ESP32 clears the counter and refreshes the OLED.

Result

The Wi-Fi Vibration Event Counter experiment demonstrates vibration contact detection, event counting and debouncing using an ESP32 and bare SW-500D sensor.

Each accepted contact-closure event increments a counter, activates an audible buzzer, and updates the SSD1306 OLED.

The ESP32 also provides a local Wi-Fi dashboard for viewing event information and resetting the counter.
