Aim

To develop a smart queue management experiment using an ESP32 NodeMCU-32S, SSD1306 OLED display, 4×4 matrix keypad and active buzzer, allowing users to generate, call, and reset queue tokens using both a physical keypad and a Wi-Fi web dashboard.

About the Experiment

QueueEase demonstrates a digital token-based queue management system. The ESP32 maintains a common queue state accessible through the keypad and browser dashboard.

Pressing A on the keypad generates a sequential token. Pressing B calls the next waiting token. Pressing C resets the queue, and pressing D refreshes the OLED display.

The OLED displays the token currently being served and the number of waiting tokens. The buzzer provides audible feedback for queue operations.

The web dashboard displays the total generated tokens, called tokens, waiting count and latest operation. Both interfaces update the same queue variables.

Queue Logic

Parameter Description
Generated Total tokens issued since reset
Called Total tokens called since reset
Waiting Generated minus Called
Current Token Most recently called token
Maximum Token T-999
Important: Token numbering starts at T-001. T-000 represents the initial or reset state and is not an issued queue token. The queue is stored in RAM and resets when the ESP32 restarts.

Connection Precautions:

The keypad ribbon pin order must match the actual R1–R4 and C1–C4 terminals. Different keypad models may use different connector ordering.

The OLED must support the selected 3.3V supply and I²C logic levels. Check its I²C address if the display does not initialize.

Use a compatible low-current active buzzer or a transistor driver if the buzzer requires more current than a GPIO can supply.

Token Generation

Each generate command increases the generated-token counter by one. Tokens follow the format T-001, T-002, T-003 and so on. The program stops issuing tokens when the counter reaches 999.

Calling the Next Token

The Call command advances the called counter only when one or more tokens are waiting. When the queue is empty, the buzzer gives an error-feedback tone.

Reset Operation

Reset returns the generated and called counters to zero, clearing the queue.

OLED Display

The OLED displays the latest called token and waiting count. It is refreshed periodically and after queue actions.

Wi-Fi Dashboard

The ESP32 serves a local HTML dashboard. Browser commands update the same counters as physical keypad commands, ensuring synchronized operation.

Procedure

  1. Arrange the ESP32 NodeMCU-32S, SSD1306 OLED, 4×4 keypad, active buzzer, breadboard and jumper wires.
  2. Connect OLED VCC to 3V3 and GND to GND.
  3. Connect OLED SDA to GPIO21.
  4. Connect OLED SCL to GPIO22.
  5. Connect the four keypad rows to GPIO13, 14, 16 and 17.
  6. Connect the four keypad columns to GPIO18, 19, 23 and 25.
  7. Connect the active buzzer signal to GPIO27.
  8. Connect the buzzer ground to GND.
  9. Verify the wiring and actual keypad pin order.
  10. Open Arduino IDE.
  11. Install the ESP32 board package, U8g2 and Keypad libraries.
  12. Select the appropriate ESP32 NodeMCU-32S board settings.
  13. Copy the complete sketch from Explore the Code.
  14. Set USE_WOKWI to 0 for physical hardware.
  15. Enter your Wi-Fi SSID and password.
  16. Verify and upload the sketch.
  17. Open Serial Monitor at 115200 baud.
  18. Observe the initial OLED token T-000 and waiting count 0.
  19. Press A and verify that a token is generated.
  20. Press A again and verify the generated count increases.
  21. Press B to call the next waiting token.
  22. Press D to refresh the OLED.
  23. Open the ESP32 IP address in a browser on the same Wi-Fi network.
  24. Use the dashboard Generate and Call commands.
  25. Verify the OLED and dashboard reflect the same queue state.
  26. Press C or use Reset Queue and verify all counters reset.

Explore More: Matrix Keypad

A 4×4 matrix keypad uses four row lines and four column lines. The Keypad library scans the matrix to detect pressed keys.

Explore More: Shared Queue State

The keypad and dashboard use the same lastGenerated and lastCalled variables, so both interfaces operate one queue.

Explore More: Token Numbering

Each generated token receives a sequential number. The displayed identifier is formatted with leading zeros.

Explore More: Web Dashboard

The ESP32 hosts an HTTP server. Browser commands are submitted through POST requests and queue information is returned through the JSON API.

Result

QueueEase demonstrates an ESP32-based smart queue management system using a 4×4 keypad, SSD1306 OLED and active buzzer.

Users can generate, call and reset tokens through the physical keypad or the local Wi-Fi dashboard. Both interfaces share the same queue state and display the current token and waiting count.
