Aim

To build a smart queue management system where tokens can be generated, called and reset using a 4×4 keypad or Wi-Fi dashboard, with OLED status and buzzer feedback.

About the Experiment

The ESP32 hosts a local web dashboard and processes keypad commands. Both interfaces share one queue state. The OLED shows the token currently being served and the number of waiting tokens.

Working Principle

Keypad or browser action→ ESP32 queue logic→ Token count updated→ OLED and dashboard refresh→ Buzzer feedback

Procedure

  1. Connect OLED, keypad and buzzer according to the circuit table.
  2. Install the U8g2 and Keypad libraries in Arduino IDE and select the ESP32 board.
  3. For physical hardware, set USE_WOKWI to 0 and enter your own Wi-Fi credentials in the sketch.
  4. Upload the program and open Serial Monitor at 115200 baud.
  5. Open the IP address displayed in Serial Monitor on a browser connected to the same network.
  6. Press keypad A to generate a token, B to call the next token, C to reset, or D to refresh the OLED. The same actions are available in the dashboard.

Expected Output

The OLED shows QUEUEEASE, the current serving token and waiting count. The web dashboard displays generated, waiting and called counts. The keypad and dashboard operate on the same queue state; the buzzer responds to queue actions.

Result

A smart queue management experiment with synchronized keypad, OLED and browser control is implemented.

What You Learn

ESP32 GPIO interfacing, keypad matrix scanning, I²C OLED displays, buzzer output, Wi-Fi web servers and shared application state.
