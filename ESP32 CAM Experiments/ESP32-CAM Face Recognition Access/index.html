Aim

To design a face-recognition-based access-control prototype using an AI-Thinker ESP32-CAM, SH1106 OLED, servo motor and buzzer, with browser-based face registration, recognition, manual door control and automatic relocking after approximately 5 seconds.

About the Experiment

The ESP32-CAM Face Recognition Access experiment demonstrates a camera-based access-control prototype.

The onboard camera captures JPEG images and sends them to a browser over a local Wi-Fi network.

The browser uses face-api.js to detect faces, create a mathematical face descriptor during registration, and compare subsequent faces with the registered descriptor.

When the browser recognizes an authorized face, it sends an unlock command to the ESP32-CAM.

The servo motor moves to the configured unlock position of 90°. After approximately five seconds, it returns to the locked position of 0°.

If a face is classified as unknown, the browser sends a denied-event command and the buzzer produces three short warning sounds.

The SH1106 OLED displays the access state, while the web dashboard includes recognition controls and manual lock/unlock buttons.

Important:

Face recognition is performed in the browser, not on the ESP32-CAM. The browser must be able to load the face-api.js library and its models. An internet connection may be required for these external resources. The camera and control dashboard operate over the local Wi-Fi network.

Face descriptors are sensitive biometric information. The example stores a registered descriptor in the browser's local storage. Use consented test subjects only, and clear stored descriptors after the demonstration.

This is a teaching demonstration. The local HTTP commands are not authenticated, and face recognition alone is insufficient for securing a real door or protecting access to people or valuable property.

Hardware Precautions:

Servo motors may draw significant startup current. Use a suitable regulated 5V source for the servo and connect its ground to the ESP32-CAM ground.

GPIO2 and GPIO15 are ESP32 boot-strapping pins. Connected hardware must not force unsuitable levels during flashing or startup.

The USB-to-TTL programmer must use 3.3V UART signal levels, even if the ESP32-CAM receives a regulated 5V input at its 5V supply pin.

If the buzzer draws more current than a GPIO can safely provide, use an appropriate transistor driver.

Face Registration

The user captures a face in the browser dashboard. The browser processes the captured image and stores its face descriptor locally.

Face Recognition

The browser compares new face descriptors with the authorized descriptor using face-api.js.

Access Granted

When a matching face is recognized, the ESP32-CAM receives an unlock command and moves the servo to 90°.

Access Denied

For an unknown face, the browser sends a denied-event command. The OLED displays DENIED and the buzzer produces warning beeps.

Automatic Relock

The ESP32-CAM uses millis() to return the servo to its 0° locked position after approximately five seconds.

Procedure

  1. Arrange all required components.
  2. Connect OLED SDA to GPIO13.
  3. Connect OLED SCL to GPIO14.
  4. Connect the OLED power and ground.
  5. Connect the servo signal wire to GPIO2.
  6. Connect the servo to a regulated 5V supply.
  7. Connect servo ground and ESP32-CAM ground together.
  8. Connect the buzzer control to GPIO15.
  9. Verify all GPIO and power connections.
  10. Connect the USB-to-TTL programmer.
  11. Connect GPIO0 to GND for flashing.
  12. Open Arduino IDE.
  13. Install the ESP32 board support package.
  14. Install U8g2 and ESP32Servo libraries.
  15. Select AI Thinker ESP32-CAM board.
  16. Create ESP32_CAM_Face_Recognition_Access.ino.
  17. Copy the complete sketch from Explore the Code.
  18. Enter Wi-Fi credentials.
  19. Verify and upload the sketch.
  20. Disconnect GPIO0 from GND and restart the ESP32-CAM.
  21. Open Serial Monitor at 115200 baud.
  22. Note the printed IP address.
  23. Open the IP address in a browser on the same network.
  24. Ensure face-api.js and its models have loaded.
  25. Click CAPTURE AUTHORIZED FACE using a consenting test subject.
  26. Click START RECOGNITION.
  27. Present the registered face in front of the camera.
  28. Observe the access-granted event and servo movement.
  29. Verify automatic relocking after approximately five seconds.
  30. Test an unknown face and observe the denied indication.
  31. Test the manual LOCK and UNLOCK controls.

Result

The ESP32-CAM Face Recognition Access experiment demonstrates browser-based face recognition with a servo-controlled prototype lock, SH1106 OLED indication and buzzer feedback.

Authorized recognition commands a temporary unlock, while an unknown face produces a denied indication. The system automatically commands the servo back to the locked position after approximately five seconds.
